## 1 · B-1 — a fixed–fixed beam under UDL now solves

`BeamModel._node_positions()` placed nodes only at supports, loads and
load-segment ends. A fixed–fixed beam under a full-span UDL therefore had
exactly two nodes and four DOF, every one of them restrained, and `solve()`
rejected the most common indeterminate case in any textbook with *"Beam is
fully constrained; nothing to solve"*.

**The physics was always right — only the mesh was too coarse.** `_refine()`
now splits any gap longer than a quarter of the modelled span.

Measured against the closed forms, which it had never been able to reach:

| quantity | got | exact |
|---|---|---|
| M at the ends | −30.000 kN·m | −wL²/12 = −30 |
| M at midspan | +15.000 kN·m | +wL²/24 = +15 |
| δ at midspan | −2.1088 mm | wL⁴/384EI = −2.1094 |
| R at each end | 30.000 kN | wL/2 = 30 |

Two things worth recording:

* **Nothing else moved, and accuracy improved.** Cubic-Hermite elements with
  consistent load vectors are nodally exact for these load types, so the extra
  nodes change no answer — they only make the M/EI integration finer. The
  simply-supported UDL deflection went from 2.2e-4 to **5.6e-5** relative
  error, and the cantilever tip from 2.8e-4 to **1.7e-5**, purely as a side
  effect.
* **The cost is bounded and falls only on coarse models.** Capping each gap at
  span/4 adds at most four elements whatever the load layout, and the cap is
  taken from the span the stations actually cover rather than `self.L`, so an
  out-of-range coordinate cannot make the mesh explode. Measured: a beam with
  4, 10 or 20 point loads gets **the same mesh it had before** (6, 12, 22
  nodes) because its own stations are already dense enough. Sparse models pay
  0.02 s → 0.19 s.

A genuine mechanism still raises — `test_a_genuine_mechanism_is_still_rejected`
guards against the fix turning a real error into silence.

## 2 · C-1 — the Cable tab no longer reports two different peak tensions

`element_tension()` divides H by each element's **chord** direction. That is
exact for the element, but not for the cable *at* a support: the end element
runs from the support to the first interior node, and its chord is always
flatter than the true tangent there. Since the peak tension is normally at a
support, the reported maximum came out low — on the unsafe side — and
disagreed with the tab's own tension diagram, which reconstructs its own
continuous curve.

`tension()` now computes the two support nodes exactly. H is the horizontal
component everywhere and the vertical component at a support is exactly that
support's reaction, so `T = hypot(H, V)` — no discretisation at all.

**On the tab's own built-in examples, results panel vs diagram:**

| example | before (panel / diagram) | after |
|---|---|---|
| parabola | — | 31.83 / 31.83 kN |
| catenary | **25.48 / 25.66 kN** | **25.66 / 25.66 kN** |
| point load | — | 45.23 / 45.23 kN |

Against the exact catenary at the app's default `n_elem = 60`:

| sag / span | before | after |
|---|---|---|
| 0.161 | −0.52 % | −0.0078 % |
| 0.355 | −1.20 % | −0.0020 % |
| 1.026 | −1.62 % | −0.0001 % |
| 7.321 | −1.67 % | −0.0005 % |

The old error also converged only **first order**, so refining the mesh was the
only escape and an expensive one. It is now mesh-independent:
`test_peak_tension_does_not_depend_on_the_mesh` asserts 10 elements agree with
200. Interior nodes are untouched — `test_interior_nodes_are_untouched_by_the_end_correction`
asserts they still equal the averaged element values exactly.

The stress check reads `T_max`, so this was the unconservative number feeding
the code check. It now reads the right one.

## 3 · B-3 — distributed loads are drawn to scale

Every load arrow was a fixed 30 px whatever the intensity, so a 0 → 60 kN/m
triangular load was drawn identically to a uniform one, and the non-uniform
branch computed its own shape function and then never used it. The load
picture is the check an engineer makes before pressing Analyze, and it could
not show a load shape at all.

Arrows are now scaled against the largest intensity in the model and the chord
above them follows the real q(x). Measured arrow lengths:

| load | before | after |
|---|---|---|
| uniform w = 20 (control) | 30 → 30 px | 30 → 30 px |
| triangular 0 → 60 | 30 → 30 px | **3 → 30 px** |
| trapezoidal 20 → 60 | 30 → 30 px | **12 → 30 px** |
| q(x) = 10x | 30 → 30 px | **3.7 → 30 px** |
| q(x) = 30·sin(πx/L) | 30 → 30 px | **5 → 30 px** |

The trapezoid figure is the arithmetic check: with a 3 px floor and a 30 px
maximum, an intensity ratio of 20/60 must give 3 + 27·⅓ = 12 px. It does.
Uplift ordinates hang below the beam, so a load that changes sign now crosses
the beam line instead of being drawn as though it pushed down. Confirmed by
screenshot with a ramp on one half and a sine on the other.

## 4 · B-4 / B-5 — the Beam tab no longer accepts nonsense silently

**B-4.** `q()` tests `x1 <= x <= x2`, unsatisfiable when x1 > x2, so a load
entered right-to-left contributed **nothing at all** — zero reactions, zero
moment, no warning. `add_dload()` now normalises, carrying the intensities
with their own ends so a ramp does not come back flipped. The test is
parametrised over `(w, w)`, `(0, 60)` and `(60, 0)` for exactly that reason.

**B-5.** Nothing checked coordinates against the beam's own length, so a
support or load at x = 99 on a 6 m beam was accepted and silently extended the
mesh to 99 m while `model.L` stayed 6.0 — a 10 kN load came back as a 155 kN
reaction. `BeamModel` now refuses any station off the beam, and the four
`_add_*` dialogs check at entry so the user is told while the number is still
in front of them. `x = 0` and `x = L` remain valid, which is where supports
normally live.

The Perforated Beam tab fixed the same reversed-load hole on 2026-09-07 and
Arch never had it; Beam was the last one out of step, and inconsistent with
itself (it already normalised its *non-uniform* loads).

## 5 · A-5 — the Arch diagram pane is legible again

Each caption was anchored at the **same y** as its panel's `max ±…` readout,
with a wrap width spanning the whole panel, so the two ran straight through
each other. Overlapping text items in the diagram canvas:

| window | before | after |
|---|---|---|
| 1500 px | 7 | **2** |
| 1000 px | 22 | 18 |
| 800 px | 20 | 16 |
| 700 px | 23 | 19 |

**Every caption × `max ±…` collision is gone at every width.** Three changes:

* captions are fitted to the panel — full text, then name only, then symbol
  (`N (kN)`, `σ (kN/cm²)`), so the quantity is never unidentifiable;
* a strip is reserved on the right, and when a panel is too narrow to hold
  both, `max ±…` drops to the panel's bottom-right instead of overprinting;
* the two reaction readouts, previously anchored to opposite edges of a panel
  narrower than either of them (**184 px of overlap even at 1500 px**), stack
  onto two lines when they will not fit.

The pane's own header was wider than its column, and Tk centres an over-wide
label and clips **both** ends — it read *"): axial N … hover over any arch
outline for"*, having lost its own first word. Shortened, and given a
`wraplength` that tracks the column so it wraps instead of clipping.

Confirmed by screenshot: the FIBRE STRESS header, previously an unreadable
pile-up of overlapping glyphs, now reads cleanly with its `max ±5.16` beside it.

**What remains, honestly.** The counts above do not reach zero at narrow
widths, and the residue is a *different* problem: axis tick labels colliding
with each other (`-150` × `-100` × `-50`) when a quarter-panel is under
200 px. That is tick density not adapting to the panel, not the caption bug,
and it is recorded as a new low finding rather than quietly folded in here.

## 6 · A-6 / A-7 / A-2 — the Arch tab validates its inputs

**A-6.** A point load is assembled onto the *nearest* node, which for any x
beyond the springings is a support — so an out-of-span load was accepted,
moved onto the support, and carried by nothing. Global equilibrium still
closed (ΣFy was right in every case), so nothing looked wrong. Now refused, at
entry and in `solve()`. The springings themselves stay valid.

**A-7.** A distributed load whose domain missed the span integrated to zero and
vanished. Now refused. Reversed entry (`x1 > x2`) was already handled correctly
and still is — there is a test saying so, so nobody "fixes" it later.

**A-2.** `ArchModel(n_elem=0)` divided by zero inside `nodes()`. It was never
reachable from the UI (which clamps with `max(4, …)`), so this is defensive
only — but the model layer is now safe when driven from a test or a script.

## 7 · B-7 / C-3 / A-4 — the three tabs now have physics tests

4 791 lines of solver had no physics coverage between them. Three new modules,
53 tests:

| module | tests | pins |
|---|---|---|
| `test_beam_math.py` | 26 | 13 closed forms, B-1, B-4, B-5, mechanism detection |
| `test_cable_math.py` | 11 | parabola, catenary, point load, C-1 and its mesh-independence |
| `test_arch_math.py` | 16 | three-hinged closed forms, funicularity, A-2, A-6, A-7 |

The best of these need no reference values at all, so they survive a change of
mesh, element or units: a parabolic arch under UDL must have **zero moment
everywhere**; a three-hinged arch must have **zero moment at its crown hinge**;
a reversed load must give **the same answer** as the same load entered
forwards; and the results table must report **the same peak tension as the
diagram beside it** — that last one is C-1 in a single line.
