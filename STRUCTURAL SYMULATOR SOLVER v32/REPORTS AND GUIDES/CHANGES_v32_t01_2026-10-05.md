# v32 t 01 · 05-10-26

The first numbered round of changes on v32. `t` for the Truss tab, which is
what most of it is about; `01` because it is the first; `05-10-26` the day
it was cut.

The app says so itself now — the window title reads
`Structural Simulator v32 t 01 · 05-10-26 — Truss drawing`, and the
release archive is `structural_simulator_app_v32_t01_<date>_<time>.zip`.

Audience, as stated by the owner: **architecture students learning how
structures behave**, not engineers producing calculations. Everything below
was decided on that basis.

---

## 1. One layout for every tab

Six tabs had drifted into four different arrangements of the same three
things:

| Tab | Was | Now |
|---|---|---|
| Truss | panel RIGHT, fixed 235 px | panel LEFT, draggable, 340 px |
| Beam, Arch, Cable | panel RIGHT, fixed 340 px | panel LEFT, draggable |
| Cable Web | two fixed sidebars, breakpoint table | two panes, both dragged |
| Perforated Beam | panel left, draggable | unchanged — it was already right |
| Stereo | panel left, fixed 360 px | unchanged (see Not done) |

Two new widgets in `common.py` carry it:

* **`AppShell`** — toolbar on top, control panel on the LEFT behind a
  draggable sash, drawing filling the rest, an optional diagram pane under
  it behind a second sash, status bar pinned at the bottom. It generalises
  the two tabs that already had it right: Stereo put its sidebar on the
  left, Perforated Beam made the divider draggable and said why — a fixed
  width "cannot be right for everyone — the tab is used at 1280 and at
  2560".
* **`CollapsibleSection`** — a LabelFrame whose title bar folds the body
  away, with the title left readable so the control stays discoverable.

**Who owns the width.** The panel asks for what its content needs, yields to
a third of the window when the window cannot afford that, and stops doing
either the moment the user drags the sash — after which the number is
theirs and auto-fit is a no-op. This was added because the tests caught a
regression: with the panel refusing to give ground, the Arch tab mapped 45
controls at 1600 px and 40 at 900 px.

## 2. The Truss toolbar, on the Stereo model

Five groups in a fixed order — **TOOLS · EDIT · VIEW · ANALYZE · OUT** —
the order the Stereo tab already read in. Beam, Arch and Cable moved their
Analyze ahead of their Excel buttons to match, so every tab now reads the
same way.

* `Examples ▾`, `View ▾`, `Report ▾`, `Excel ▾` replace twelve separate
  buttons.
* **Undo and Redo get buttons**, greyed when empty, each captioned with
  what it would undo. The stack and its labels already existed; only
  Ctrl+Z reached them.
* **Analyze is in the toolbar AND at the top of the panel.** It used to be
  the thirteenth block down a 235 px scrolling column — roughly 900 px in.
* **A Pan tool, and space-drag.** `ZoomCanvas` panned on the middle button
  only, which most laptop trackpads do not have: on those the view could
  not be moved at all.
* **Fit**, via a new `ZoomCanvas.fit_to_bbox`. `Reset view` goes to the
  origin, which stops being the model as soon as you build away from it.

## 3. Perspective and parallel in the PDF (new feature)

The 3D view has offered both since the camera popover landed; the PDF was
parallel-only, so a report could not show what the screen was showing.

* `stereo_reports.export_pdf` takes `projection` ('parallel' or
  'perspective') and `eye_mult`, the eye distance as a multiple of the
  model's bounding radius — so one setting means the same strength of
  perspective on a 3 m canopy and a 60 m span.
* It is read from the canvas, not asked for again: `_pdf_view_kwargs()` is
  the single place all four PDF exports get their drawing options, so a
  model being looked at in perspective prints in perspective.
* **The five orthographic elevations stay parallel whatever is asked for.**
  They carry a scale bar and a dimension grid, and both would lie under a
  projection whose scale varies with depth. Two tests pin this, one reading
  the code and one measuring two equal world lengths on a plan sheet while
  a perspective sheet eye is set.

## 4. Smaller corrections in the Truss tab

* **Units.** Fifteen places printed the literal string `kN`, so with AISC
  selected the panel read kip and the drawing read kN in the same window.
  All now go through the unit layer: canvas labels, hover tooltips, the
  free-body diagrams, the selection panel, the status line.
* **Reactions are no longer green.** `CD` (deformed) was `#1D9E75` and `CR`
  (reaction) `#2ecc71` — two greens four rows apart in the same legend.
  Reactions are `#6A1B9A`; nothing else on a truss canvas is purple.
* **`Ctrl+X` no longer means Redo.** Every other application binds it to
  Cut, so pressing it expecting to cut silently re-applied an undone edit.
  Redo is `Ctrl+Y` / `Ctrl+Shift+Z`; `Ctrl+S` saves.
* **A model can be saved before it is analysed.** `truss_reports.export_excel`
  always handled `results=None` — only the UI guard refused, so a student
  who had placed twenty joints and had to leave could not save them.
* **Support types are named for what they do** — "Roller (slides ↔)"
  rather than `rollerX`, on the combobox, the hover tooltip, the selection
  panel and the glyph caption. The stored keys are unchanged, so no saved
  model or workbook changes meaning.
* **The diagram caption follows the mode** instead of describing the
  Vierendeel silhouettes in all three.
* The CAD precision bar moved into the work pane above the drawing, where
  Simple mode still hides it.

Measured on this machine (Python 3.12 + tkinter under Xvfb), the whole
suite, and the same commands run against **pristine v32** for comparison:

| | pristine v32 | after this round |

| `tests/test_stereo_app.py` (1 h 52 m) | — | **1 000 passed** |
| **total passing** | 3 912 | **3 937** |

**The one failure is pre-existing and not from this round.**
`test_truss_layout.py::test_analysis_still_shows_diagrams_after_a_report_window_opened[_show_rod_calculations_report]`
fails identically on pristine v32, with
`TclError: image "pyimage1" doesn't exist`. It passes when that file is
run on its own: an earlier test in the same process leaves a matplotlib
PhotoImage behind on a Tk root that has since been destroyed, and the
report window's equation images then cannot be built. It is a defect in
the suite's root handling, not in the app, and it was left alone because
fixing it is not what this round is about.

New: `test_pdf_projection.py` (12), `test_appinfo_iteration.py` (11), plus
additions to `test_truss_layout.py`.

Three existing tests changed, each because the contract deliberately did:
the build stamp now carries the round, `appinfo.build_info()` returns it as
a third value, and the diagram pane is a PanedWindow pane rather than a
packed frame — that last one re-asserted as behaviour (the pane comes back
after an analysis with a report window open) rather than as the packing
mechanism it used to check.

Two tests caught real mistakes while this was being written, and are worth
naming: the guide-vs-code check in `test_notices.py` found a control the
USER_GUIDE still told people to press after it had been renamed, and the
layout test found a slider built and never packed.

## Not done, and why

* **Stereo has no sash.** Its panel is already on the left, so only the
  draggable width is missing. Left alone deliberately: it is the tab the
  layout was modelled on, and rewriting its `_build_ui` in the same round
  would make it harder to see what the model was.
* **The Truss tab's teaching layer was already there.** An earlier plan
  proposed a mechanism diagnosis, dashed zero-force rods, live re-solve
  and progressive disclosure. v32 has all four already — `truss_stability.py`
  does a proper null-space analysis and animates the mechanism, which is
  better than what was proposed — so none of it was ported. The same goes
  for the axial-force chart: v32's `_draw_diagrams_only` already draws one
  signed N bar per rod whenever no rod bends.
* **Load-path visualisation** — animated chevrons tracing a load to the
  supports. Still the largest unbuilt teaching feature.

## Open question

The unit selector names design codes (CIRSOC, Eurocode, NBR, CSA, AISC) but
only CIRSOC 301 is implemented: `cirsoc_301.py` supplies the φ factors for
every plate check whichever entry is chosen, so picking "AISC 360" changes
kN to kip and nothing else. Either rename the entries to unit conventions,
or keep the code names and state under the selector which code the checks
come from. The second is recommended and is **not yet applied** — it needs
the owner's decision.
